# toMarkdown PDF probe — results (2026-10-15)

Point-in-time numbers behind [ADR-031](adr/031-to-markdown.md). Harness,
prototype converter, AES shim and raw results: `scratch/tomarkdown-probes/` in the main checkout
(gitignored). The test PDFs were not kept; they are public (see Corpus) or
regenerated by `tools/encrypt.py`.

## Setup

- pypdf 6.20.1 (BSD-3, pure Python, no required deps) copied into a scratch
  copy of `runtime/guest`, `import pypdf` + allowlist entry in `app.py`,
  built with the repo's `componentize-py` (0.25.1).
- Each (file, mode) = one `anyrt run pdfprobe@v1 --kernel <probe kernel>`
  against the `tests/test_rt_e2e.py` fake any server (plus
  `/v1/local/insert`, see Side findings), PDF served over `http.get` →
  `bytes(blob)`. Fuel and wall time come from the run's own result line.
- Native baseline: the same program source on host CPython 3.14.
- Modes: `plain` = `page.extract_text()`; `md` = the prototype passes
  (visitor lines, headings by size, header/footer trim, paragraphs,
  dehyphenation, lists); `read` = blob read only; `open` = `PdfReader` +
  page count.

## Corpus (20 files)

pypdf's own `py-pdf/sample-files` (trivial, LibreOffice, pdflatex 4-page,
password, image-only, GeoTopo 117 pages, forms, Google Docs, Arabic, PDF/A,
LaTeX two-column, cropped/rotated), arXiv 1706.03762 (Attention, 15 pages)
and 1810.04805 (BERT, two-column, 16 pages), IRS Form 1040 (2 pages), ISO
32000-1 (the PDF spec, 756 pages, 22 MB), and four encrypted copies of the
Google Docs file (RC4-128, AES-128, AES-256, AES-256 owner-password-only).

- ~11 G fuel per second of wall time on this box; the kernel runs pypdf at
  ~3× native for documents of real size (small files are dominated by the
  fixed ~0.06 G cell start).
- `md` costs 1–3 % over `plain`: the passes are cheap, extraction dominates.
- Kernel and host output identical: 28/28 comparisons, same character
  counts.

Fixed vs per-page cost (fuel):

| file | blob read | open | 10 pages | 30 pages |
|---|---|---|---|---|
| Attention (2.2 MB) | 0.31 G | 0.81 G | 5.64 G | 23.44 G (all 15) |

- Blob read ≈ 0.13 G/MB. Opening scales with size and page count: the spec

- Text pages: 0.34 G (GeoTopo 11–30), 0.41 G (spec 11–30). Figure-heavy
  pages: 3.6 G each (Attention 11–15, the attention visualizations — every

## Encryption

| handler | stock pypdf in kernel | with the `Crypto` shim |
|---|---|---|
| RC4-128 | ok (1.08 G) | ok |
| AES-128 | `DependencyError: cryptography>=3.1 is required` | ok (2.42 G) |
| AES-256 | same | ok, but **42–45 G** |
| AES-256 owner-only | same | ok, but **47–50 G** |

The shim (pure-Python table AES, ECB/CBC, verified on 1800 vectors against
`cryptography`) satisfies pypdf's pycryptodome provider probe without
touching pypdf. AES-256's R6 key derivation (≥ 64 rounds of AES-CBC over
the password hash) takes 1.3–1.5 s natively and nearly the whole run budget
in the kernel. One file, no extraction left.

## Quality (prototype passes)

- **Body text good**: paragraphs reflow, two-column reading order correct
  (BERT, LaTeX multicolumn: pypdf follows the content stream, which LaTeX
  writes column by column).
- **Headings by size alone are noisy**: BERT's figure 1 labels became ~30
  headings; Attention's level order inverted (the arXiv stamp and the
  license note outrank the title). Bold-at-body-size headings ("1
  Introduction" in BERT) are missed. → ADR §3: bold signal + figure guard.
- **Dehyphenation** joins compound words broken at a line end only into a
  lowercase continuation; "English-to-German" still lost its hyphen once.
- **Forms**: the IRS 1040 labels come through; field values live in
  AcroForm fields, not page text → ADR §3 pass 5.
- **Image-only** file: 0 characters, `scanned: true`. The flag also fires on
  a legitimately tiny document (one Arabic line, 19 chars): it is a hint to
  the caller, not a verdict.
- Fonts: pypdf logs "fontTools is required to fully parse the encoding of a
  CFF Type1 font" on the spec; extraction still succeeds.

## Kernel size

| build | today's kernel | + pypdf + codecs |
|---|---|---|
| clean tree (no `__pycache__`, = CI) | 25.1 MB | 50.7 MB |
| warm tree / `compileall` first | 23.0 MB | 28.6 MB |

Without `.pyc` files the pre-init snapshot keeps the compile's heap. pypdf's
578 KB `adobe_glyphs.py` dict literal makes it +25.6 MB clean vs +5.6 MB
precompiled. `python -m compileall runtime/guest` before `componentize`
gives the warm size from a clean tree.

## Side findings

- **Lazy stdlib codecs**: `unknown encoding: utf-16-be` on the first kernel
  run (ADR-002 §4's `cp437` rule again). All the codecs pypdf names,
  CJK included, import fine once pre-imported.
- **`anyrt run` without trace streaming has no blob directory**: the e2e
  fake lacks `/v1/local/insert`, so the writer stayed buffered
  (`trace streaming unavailable … will write at run end`), and
  `bytes(http.get(url).blob)` failed `blob_missing` in the same run. The
  same holds for any server where streaming fails.
- **`io` is proxied, not refused** (ADR-002 §4 tier 2): `io.BytesIO` is
  available for wrapping bytes for `PdfReader`.
